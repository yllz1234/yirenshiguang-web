# 一人食光

一人食菜谱匹配网页。项目使用原生 HTML、CSS 和 JavaScript，没有后端、账号系统、构建步骤或 npm 依赖。

交接记录中的演示地址：[yirenshiguang.bigapple.work](https://yirenshiguang.bigapple.work/)。演示站与本仓库分别维护，线上内容以实际部署的版本为准。

## 本地预览与部署

在项目目录运行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。部署时把 `index.html` 和 `assets/` 一起放到静态站点根目录，保持相对路径。唯一外部页面资源是 Google Fonts 的 Noto Sans SC；无法加载时使用系统字体。

## 三个入口

| 入口 | 行为 |
| --- | --- |
| 按食材配菜 | 按忌口、可用锅具和时间筛选。完整匹配的菜排在前面，其后是缺一两样主要食材的方案（列出缺项），「换一道」可在这些方案之间切换。食材按钮只列出至少有一道菜用作主要食材的项目；其他食材可用「其他食材」输入框补充，仍会参与「这道会用」的判断。无匹配时提示用户调整食材或条件。 |
| 对话点菜 | 在同一菜谱库里按关键词匹配，支持食材、菜名、常见口味、常见忌口及随机推荐。每条消息独立匹配，不记忆上一轮对话；但页面上设置的忌口、锅具和时间条件对它同样生效。 |
| 今晚盲盒 | 从有配图的菜谱里按盲盒条件抽取，并同样遵守页面上设置的忌口、锅具和时间，优先选择能用上已选食材的菜。有效菜池变化时重新洗牌；同一轮不重复。 |

菜谱卡显示一人份参考用量、调料、锅具、步骤和替代方案。配菜结果会区分哪些已选食材能用在这道菜里；继续配菜只使用上一道没用上的食材。这个流程不跟踪食材的实际库存或剩余克数。

收藏和最近看过（最多 8 道）存于当前浏览器的 `localStorage`（键名沿用 `yirenshiguang_stats_v2`，旧版用户的收藏会保留）。记录不上报，也不跨浏览器或设备同步；浏览器禁止写入时只保留本次页面会话。逐步勾选的烹饪进度保留在当前卡片中，刷新页面不会保留。

## 维护菜谱

`index.html` 包含样式、页面和交互逻辑。菜谱集中在其中的 `DISHES`；图片放在 `assets/`。目前 17 道菜谱各有一张配图。新增的 7 张配图为生成的示意图，以 WebP 格式存放。页面菜谱数量由 `DISHES` 计算。

| 字段 | 用途 |
| --- | --- |
| `id`、`title`、`img` | 唯一标识、菜名和相对图片路径。`img: null` 时隐藏图片区，该菜不参与盲盒。 |
| `needs` | 主要食材，用于计算缺项。名称使用 `INGREDIENT_GROUPS` 中的标准名称；别名在 `ingredientAliases` 定义。常备调料和配菜仍以完整用料为准。 |
| `toolKeys`、`alternateToolKeys` | 每组内的锅具都要满足；如有可替代的一组，用 `alternateToolKeys` 表示。 |
| `minutes`、`spicy` | 参考时间和原做法是否必须用辣味。可选辣味应在用料和步骤里都标明。 |
| `tags`、`desc`、`amounts`、`seasoning`、`tools`、`steps` | 菜谱卡内容。用量、调料和步骤应互相对应；注明生重、净重或熟重等口径。 |
| `subs` | 缺料替代建议，可包括主料和调料。已有忌口条件时，含冲突配料的替代建议会隐藏。 |

编辑后至少走查桌面和窄屏、完整/缺料/无匹配配菜、忌口和锅具过滤、聊天点菜、连续开盲盒及收藏后刷新页面。

## 仍有限制

- 这是固定菜谱库和关键词匹配。忌口只依据代码已列出的用料和调料，无法判断不同品牌的复合调味料或未列成分；也没有严格素食或过敏原筛查。
- 菜谱内容、参考用量和时间仍需试做校对。添加菜谱或图片后需要重新部署静态文件。
- 原设计稿：Ardot 画布 `720406084232457`。主色为珊瑚橙 `#FF5A5F`，按钮深红 `#C93F45`，背景暖奶油色 `#FDF8F1`。
