## 1. 项目概览

「一人食光」是一个面向独居用户的**一人食菜单生成器**。核心解决两个问题：一个人不知道吃什么、买了食材用不完。

产品提供三个入口，其中**食材配菜是主路径**：

| 入口 | 作用 | 在页面中的位置 |
|---|---|---|
| 食材配菜（主路径） | 勾选冰箱现有食材 + 设置忌口/锅具/时间 → 生成带精确用量的菜谱 | 第 1 屏下方，页面主区块 |
| 对话点菜（辅助） | 用聊天方式描述需求 → 返回菜谱卡 | 第 2 个功能区块 |
| 今晚盲盒（辅助） | 开盒动画随机出一道菜，适合拉新 | 第 3 个功能区块 |

## 3. 技术栈

**零依赖、零构建。**

- 原生 HTML5 + CSS3 + JavaScript (ES6)
- 无框架、无打包工具、无 npm 依赖
- 唯一外部资源：Google Fonts 的 Noto Sans SC（字体，`<link>` 引入）
- 数据存储：`localStorage`（仅本机，不上传服务器）
- 图片：本地 PNG 文件，相对路径引用

这意味着：**复制整个文件夹到任意静态服务器即可运行**，不需要 `npm install`、不需要编译。

## 4. 本地运行

因为用了相对路径加载图片和字体，直接双击 `index.html`（`file://` 协议）可能出现图片加载问题，建议起一个本地静态服务：

```bash
# 在项目根目录执行，任选一种
python3 -m http.server 8080
npx serve .
php -S localhost:8080
```

然后访问 `http://localhost:8080`。

## 6. 核心数据结构：`DISHES`

所有菜谱集中在 `index.html` 第 646 行的 `DISHES` 数组。**新增一道菜只需往这个数组里加一个对象**，三个入口、选项筛选、收藏、盲盒会全部自动生效。

```js
{
  id: 'fanqie',                          // 唯一标识，英文
  title: '番茄滑蛋青菜盖饭',              // 菜名
  img: 'assets/dish.png',                // 图片路径；无图写 null（卡片会自动隐藏图片区）
  minutes: 15,                           // 耗时（分钟），用于时间筛选
  spicy: false,                          // 是否辣，用于「不吃辣」筛选
  toolKeys: ['炒锅'],                    // 所需锅具，用于锅具筛选
  tags: ['15 分钟', '一人份', '清淡暖胃'], // 卡片上的标签（3 个，颜色依次为珊瑚/蜂蜜/绿）
  desc: '酸甜番茄汤底，滑蛋裹着热饭，热乎下肚',  // 一句话描述
  needs: ['西红柿', '鸡蛋'],              // 需要的食材（匹配核心字段）
  amounts: [                             // 一人份精确用量（必须标明口径：熟重/生重/净重/去壳）
    '米饭 150g（熟重）',
    '西红柿 1 个（约 150g 净重）',
    '鸡蛋 2 个（约 100g 去壳）',
    '小青菜 100g（净重）'
  ],
  seasoning: '盐 2g · 糖 3g · 生抽 5ml · 食用油 10ml',  // 调料
  tools: '炒锅（不粘更好）+ 电饭煲或用剩饭',            // 锅具说明
  steps: [                               // 步骤（烹饪模式会逐条变成可勾选按钮）
    '番茄切块，中火炒 2 分钟至出汁，加半碗水煮开',
    '淋入打散的蛋液，静置 5 秒再轻轻推散',
    '放青菜烫 30 秒，加盐和糖调味',
    '浇在热米饭上，撒葱花开吃'
  ],
  subs: {                                // 缺料替换方案：食材名 → 替代做法
    '西红柿': '番茄酱 2 勺 + 清水 50ml',
    '青菜': '菠菜 / 生菜 / 娃娃菜',
    '鸡蛋': '嫩豆腐半盒（素食版）'
  }
}
```

### 新增 / 修改菜谱的注意事项

1. `needs` 里的食材名要和食材选项列表（`INGREDIENT_OPTIONS`）里的名称**完全一致**，否则匹配不到。
2. `amounts` 必须写清重量口径，这是体验评审专门要求的。
3. `subs` 的 key 必须出现在 `needs` 里，否则不会展示。
4. 图片建议 1:1 正方形，导出宽度 ≥ 400px。

## 7. 关键实现逻辑（便于后续改动）

### 7.1 食材匹配 `rankRecipes()`
优先级从高到低：
1. `needs` 全部满足的菜谱（按 `needs` 数量降序，越具体越优先）
2. 只差 1–2 样的菜谱（会醒目标注「还差：XX」）
3. 都不满足时 → `buildGenericDish()` 用用户选的食材生成一道「自由发挥」菜，而不是硬凑一道不成立的菜

### 7.2 食材利用率 `computeUsage()`
结果卡会区分「已使用 / 未使用」食材，并解释未使用原因；提供「用剩下的 X 再配一道」按钮，走 `generateFromLeftovers()`。

### 7.3 盲盒 `drawFromBag()`
洗牌袋算法：一轮内把所有菜不重复地开完，开完才重新洗牌，避免连续开到同一道。

### 7.4 本地存储
`localStorage` 键：`yirenshiguang_stats_v2`
存储内容：各入口使用次数、烹饪模式进入次数、满意度反馈、收藏列表、最近做过（最多 8 条）。
**纯本机数据，不上传任何服务器**。清除浏览器数据会丢失。

## 8. 已知限制 / 给开发同事的说明

这部分很重要，请务必了解，避免误判产品能力：

1. **没有后端，没有真实 AI。** 对话点菜是基于 17 道人工整理菜谱的**关键词匹配**（`getResponse()` 函数），不是大模型实时生成。页面「能力说明」区块已经对用户诚实披露了这一点。
2. **没有用户系统。** 收藏、最近做过都只存在浏览器本地，换设备不同步。
3. **没有数据上报。** 使用统计只写 `localStorage`，运营方看不到任何数据。如果要做真实产品验证，这是第一个要补的。
4. **菜谱是硬编码在前端的**，改菜谱需要改代码重新部署。产品化时应该抽到后端或 CMS。
5. **无图菜谱**会自动隐藏图片区域，不展示「暂无配图」占位。目前共 17 道菜谱，其中 5 道无图：红烧排骨饭、香葱滑蛋盖饭、黑椒土豆牛肉饭、麻婆豆腐饭、拍黄瓜拌饭。补齐图片只需在这几道菜的 `img` 字段填上路径。
6. **字体依赖 Google Fonts**，国内网络环境可能加载慢，建议自托管 Noto Sans SC 字体文件。

## 9. 后续开发优先级建议

按体验评审的结论，从「Demo」走向「产品」最该补的：

- **P0** 接入真实后端 + 菜谱数据接口，把 `DISHES` 从前端搬到服务端
- **P0** 真实使用数据埋点（三个入口的使用率、完成烹饪的比例、满意度），用于判断哪个入口值得投入
- **P1** 接入真实 LLM 做对话点菜，替换关键词匹配，同时保留兜底菜谱库
- **P1** 账号系统 + 云端同步收藏
- **P2** 采购清单导出（把未使用食材和菜谱用料合成购物清单）

## 10. 部署

当前线上跑在 BigApple 静态托管（https://yirenshiguang.bigapple.work）。
